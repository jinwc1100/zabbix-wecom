## Context

`sla-wecom-notifier` 已能登录 Grafana、过滤年度 SLI &lt; 99.9% 的系统，并以 Markdown 推送企微。探索阶段已确认：

- 年度报表 uid=`afj5c5o5v3rb4f` 产出低 SLI 系统名。
- 宕机明细 uid=`cfn36wzatcpa8d`（键：`SLA服务名称`，结束列：`恢复时间`）对应**子系统**。
- 父系统宕机 uid=`cfsre5mthdr7kc`（键：`父系统名称`，结束列：`宕机结束时间`）对应**父系统**。
- 两清单对低 SLI 集合互补覆盖（约 23 子 + 18 父），精确名称匹配即可。

若展开全年宕机，单系统可达十余条、总量数百行，企微消息过长。本设计在关联输出上增加「近 1 个月明细 + 历史存在备注」。

## Goals / Non-Goals

**Goals:**

- 低 SLI 系统关联宕机明细，输出 5 字段：系统名称、年度 SLA（SLI）值、宕机开始/结束时间、系统层级（父系统/子系统）。
- 多宕机时**仅展示最近 1 个月窗口内**的记录。
- 窗口外仍有宕机时，对系统给出**备注提示**（不展开历史明细）。
- `/preview` 与 `/notify` 共用同一段 Markdown。

**Non-Goals:**

- 不修改 Grafana 看板 SQL / 面板定义。
- 不实现交互式下钻「查看历史全部宕机」的 Web UI。
- 不引入新的持久化库或消息队列。
- 不在本变更中处理企微 @ 责任人与手机号映射完善（沿用现有配置即可）。

## Decisions

### D1. 近 1 个月窗口定义

- **选择**：滚动窗口 `now - recentWindowDays`（默认 **30 天**），配置项 `sla.downtime.recent-window-days: 30`。
- **判定字段**：以 `宕机开始时间` 落入窗口为准（解析为本地时间后比较）。
- **备选**：自然月（本月 1 日 00:00 至今）——口径随「几号跑任务」波动大，故不采用默认。
- **未恢复**：开始时间在窗口内则展示，结束可为「未恢复」。

### D2. 历史备注策略

对每个低 SLI 系统，在全量匹配结果上统计：

| 近窗内条数 | 窗外条数 | 展示 |
|------------|----------|------|
| &gt; 0 | 0 | 仅列近窗明细，无备注 |
| &gt; 0 | &gt; 0 | 列近窗明细 + 备注「此前月份亦有宕机明细（共 N 条未展开）」 |
| 0 | &gt; 0 | 不列明细行 + 备注「近 1 个月无宕机记录，此前月份有宕机明细（共 N 条）」 |
| 0 | 0 | 可配置 omit，或一行「无宕机明细」 |

备注文案可配置，默认中文如上。

### D3. 父/子系统标注

- 命中父系统宕机清单 → `父系统`。
- 命中叶子宕机清单 → `子系统`。
- 双边命中（异常）→ `parent_first`，打 warn 日志。

### D4. 模块划分

```
AnnualSliService      → 低 SLI 列表
DowntimeQueryService  → 拉两套宕机看板并索引
DowntimeMatchService  → 关联 + 层级 + 近窗过滤 + 历史计数
SlaMarkdownFormatter  → Markdown
SlaReviewNotifyService→ 编排 preview/notify
```

时间戳统一工具：毫秒/秒/字符串 → `yyyy-MM-dd HH:mm:ss`；保留「未恢复」原文。

### D5. Markdown 结构

按「父系统 / 子系统」分组；每系统标题含名称与年度 SLI；下列近窗宕机起止；其下用引用块输出备注（若有）。

### D6. 去重

新/老版数据源可能产生同名同时段重复行：按 `(systemName, start, end)` 去重后再做近窗过滤。

## Risks / Trade-offs

- [Risk] 时间戳时区不一致导致边界日漏记/多记 → Mitigation：统一按 Asia/Shanghai 解析；与 Grafana 面板 `CONVERT_TZ` 口径对齐并在 README 说明。
- [Risk] 企微 Markdown 长度仍超限（近窗内宕机仍很多）→ Mitigation：可配置每系统最多展示 K 条，备注中说明「近窗共 M 条，仅展示前 K 条」。
- [Risk] 系统改名导致匹配失败 → Mitigation：精确匹配；未匹配走「无宕机明细」策略并日志。
- [Trade-off] 滚动 30 天 vs 自然月：滚动更稳定，但与「自然月复盘」话术略有差异 → 配置可改为自然月若业务坚持。

## Migration Plan

1. 合并配置默认关闭定时推送与 `wecom.enabled=false`，先用 `/preview` 验收近窗与备注。
2. 确认文案与数量后开启企微与定时任务。
3. 回滚：还原配置与变更前 jar；无 DB 迁移。
